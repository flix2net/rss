A free, local, zero-dependency RSS / Atom / JSON Feed extractor with a web GUI. It does the job of hosted feed-scraping actors — without an account, an API key, a run quota, or your URL list being sent through anyone else's servers.

Install

There is nothing to install. Every feature uses Node built-ins (node:http, node:fs, global fetch). No packages, no build step, no native modules.

# clone, then run — no npm install step
git clone https://github.com/flix2net/rss.git
cd rss
node src/cli.js        # opens http://127.0.0.1:5055

On Windows, after cloning, just double-click start.bat.

The hosted app works the moment you open it — no account, no install. It runs in demo mode, reading feeds through rss2json, because no real feed sends Access-Control-Allow-Origin and Pages runs no server. Demo mode caps at 10 items per feed and your feed URLs are visible to rss2json. Point the app at your own relay to lift that, or run node src/cli.js locally, where the server does the fetching itself and nothing leaves your machine.

Usage

A browser GUI for interactive work, and a headless CLI for scripts and pipelines. Both speak the same options.

GUI

node src/cli.js                 # start the server and open a browser
node src/cli.js --port 8080     # pick a port (auto-increments if busy)
node src/cli.js --no-open       # don't launch a browser
node src/cli.js --host 0.0.0.0  # expose on your LAN (see Security)

Paste feed URLs one per line, set Max items per feed, press Start (Ctrl+Enter works too). Then filter, sort, read full text inline and export. Your input is remembered in localStorage.

Headless

node src/cli.js extract https://feeds.bbci.co.uk/news/rss.xml --max 10
node src/cli.js extract feeds.txt --format csv --out news.csv
node src/cli.js extract https://x.example/feed --format ndjson | jq -r .title
node src/cli.js extract a.xml b.xml c.xml --no-content --errors

Exit code is 1 if every feed failed, 2 for bad arguments — safe to use in CI.

Output shape

items[] is flat across all feeds, so it drops straight into a spreadsheet or a jq pipeline. Export as JSON, CSV, NDJSON or Markdown.

A failed feed never aborts the batch — it lands in errors with a machine-readable code: timeout, network_error, http_status, blocked_host, too_large, empty_body, invalid_url, parse_failed.

What it handles

The parsing layer is the actual substance of this project, so it is deliberately forgiving — real feeds are malformed far more often than spec-compliant.

Four formats

RSS 2.0, Atom 1.0, RSS 1.0 / RDF, and JSON Feed 1.0 & 1.1.

Namespaces by URI

content:encoded, dc:*, media:content/group (YouTube, Vimeo), itunes:*, slash:*, georss:* — with a fallback for feeds that forget to declare prefixes.

Encodings

Honours HTTP charset and the XML declaration, maps iso-8859-1 → windows-1252 per the WHATWG spec, handles BOMs, gzip/deflate/br and redirects.

Dates

RFC 822, ISO 8601 with and without a zone, two-digit years, and Unix timestamps in seconds or milliseconds.

Broken markup

Unclosed leaf tags are implicitly closed, entities missing their semicolon are repaired, stray close tags ignored, script/style bodies dropped rather than leaked as text.

Thumbnails

Media RSS → <image> → itunes:image → image enclosures → <img> inside content HTML, largest first.

Security

A local server that fetches URLs on request is an SSRF risk if you are careless about it. These guards are on by default.

  • Binds 127.0.0.1 only. --host 0.0.0.0 exposes it to your network, and the tool has no authentication — trusted LAN only.
  • POST /api/extract requires an x-rss-extractor header, forcing a CORS preflight no third-party site can pass, so a random webpage cannot get this server to fetch URLs for it.
  • Loopback, RFC1918, CGNAT and link-local targets (including 169.254.169.254) are refused unless you opt in with allowPrivate.
  • Feed HTML is never injected into the DOM: the GUI renders every field through textContent, and a Content-Security-Policy blocks remote scripts.
  • CSV export prefixes cells starting with = + - @ so Excel will not evaluate them as formulas.
  • No telemetry, no update checks, no network calls except the feeds you name.

Limits

500 items per feed · 200 feeds per request · 12 MB per feed document · 20 s default timeout · 1 MB request body. All are single constants in LIMITS (src/feed.js) — edit and restart.

Development

node --test        # 79 tests, no framework to install

Tests cover the parser against hand-written malformed fixtures, plus a real HTTP round-trip against a local fixture server (charset decoding, gzip, 404s, timeouts, the CSRF guard, path traversal).

Contributing: fork it, branch off main, add a fixture to test/feed.test.js for any parsing behaviour you change, and open a PR. node --test must pass.
